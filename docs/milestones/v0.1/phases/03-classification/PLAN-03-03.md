<objective>
Connect triage and classification into scheduled pg-boss jobs and fill `topic_stats_15m`, the table the
board reads. Every minute, classify-batch triages new posts and classifies pending ones, and the rollup
recomputes the current and previous 15-minute buckets (plus buckets touched by new or corrected labels)
for each topic x entity x lane. Topics get active/dormant status (10 or more items in 24h). Active
topics get two-line summaries every 30 minutes. Unclassified posts are clustered into Emerging
candidates, and a nightly purge applies retention (raw_json 30 days, post text and authors 90 days,
rollups and market points kept). Reach columns get a placeholder sum and coordination columns keep
their defaults; 06-01 and 06-02 fill them. The 30-item split rule is a read-time concern for 04-01, so
rollups store raw counts only.

Interfaces fixed here for later plans (06-01 and 07-01 already expect them): `rollup/index.ts` exports
`runRollup(h, now = new Date(), opts?: { mode?: 'recent' | 'full7d' })`, `recomputeRange(h, { from, to })`
and `bucketStart(d)`. The upsert uses `ON CONFLICT (bucket_start, topic_id, entity, lane) DO UPDATE`.
Every entry point takes an injectable `now`.
Contract gap: `apps/worker/src/index.ts` belongs to 02-01. If SUMMARY-02-01 shows it does not already
call into `./jobs.js`, add exactly one import and one `await registerPipelineJobs(...)` line there.
This is a Rule 3 blocker fix: record it in DECISIONS.md and in the SUMMARY under Deviations. It is the
only file this plan may touch outside its Owns paths. No other plan runs in this wave.
</objective>

  <files>apps/worker/src/rollup/index.ts, apps/worker/src/rollup/active.ts, apps/worker/src/rollup/bucket.test.ts, apps/worker/src/rollup/rollup.int.test.ts</files>
  <action>Tests first. `bucketStart(d)` floors to 15 minutes in UTC. IST is UTC+05:30, so the boundaries
  match IST quarter-hours. Test that 2026-10-16T09:14:59+05:30 lands in the 09:00 IST bucket.
  `recomputeRange(h, { from, to })` runs one SQL statement in a transaction over posts joined to
  `effective_classifications` with `published_at` in [from, to). It buckets with `date_bin('15 minutes',
  p.published_at, TIMESTAMPTZ '2000-01-01 00:00:00+00')` and fans out entity ('all' plus each element of
  `entities`) and lane (the post's lane plus 'all'). It aggregates items, pos/neu/neg, low_conf
  (confidence = 'low'), and reach_pos/neu/neg = `sum(coalesce(p.reach_score, 0)) filter (...)` as a
  placeholder for 06-01. It leaves suspected_coordinated, burst_flag and top5_author_share at their
  defaults. Rows upsert with ON CONFLICT DO UPDATE. Rows in the range that are no longer produced are then
  deleted, so a relabel that empties a slice leaves no stale counts. Rows are sparse (items > 0 only).
  `runRollup(h, now, { mode })`: 'full7d' recomputes [bucketStart(now) - 7d, bucketStart(now) + 15m).
  'recent' recomputes the current and previous buckets plus every distinct bucket of posts whose
  classification row has `created_at >= now - 3 min` (covers new labels and corrections), limited to the
  last 7 days so it never rewrites old rollups whose posts retention may have removed. When mode is
  omitted, it is 'full7d' when now's UTC minute is 7, else 'recent'. Returns `{ mode, buckets, rows }`.
  `active.ts`: `refreshTopicStatus(h, now, minItems24h)` sets seed topics (not 'dismissed') to 'active'
  when the sum of items over entity='all', lane='all' in (now - 24h, now] is >= minItems24h, else
  'dormant'. It does not touch emerging, unclassified or dismissed rows. runRollup calls it after
  recompute, with `minItems24h` from config when SUMMARY-01-01 names the key, else
  `ACTIVE_MIN_ITEMS_24H = 10` (log ISS if the config lacks the key).
  Integration tests (DATABASE_URL_TEST, seed topics, posts plus model classifications inserted directly):
  a post with entities [isha, jio] in lane social yields rows (all|isha|jio) x (all|social) with
  items 1; a correction moving it to another topic, then a 'recent' run at now, moves the counts and
  deletes the old rows; 9 vs 10 items in 24h toggles dormant/active; a 10-day-old rollup row survives
  'full7d'; a low-confidence unclassified post increments low_conf on the unclassified topic.</action>
