<objective>
Flag manipulation without accusing anyone. The worker marks social posts in near-duplicate clusters that
reach 5 or more distinct authors within 60 minutes. Rollups fill `suspected_coordinated`, `burst_flag`
(a bucket above 4x the trailing 24h median) and `top5_author_share` (the top-5 authors' share of the
topic's 24h posts). The brief and topic pages show these only as "suspected" counts that open the
evidence drawer. There is no "organic %" and authors are never listed. Contract gaps filled here: a
per-post `posts.coord_suspected` column (migration), additive api-types fields, and evidence params
`coordinated`, `cluster` and `bucket`.
</objective>

  <action>Schema first: add `coord_suspected boolean not null default false` and `coord_detected_at timestamptz`
  to `posts`, plus a partial index `posts_coord_suspected_idx on posts (published_at) where coord_suspected`.
  Generate the migration with `corepack pnpm --filter @jio/db exec drizzle-kit generate --name coordination_flag`
  and apply it with `corepack pnpm db:migrate`. Make no other schema change.
  Tests first (Vitest), then `trust/coordination.ts`, which exports these pure functions:
  - `findCoordinatedPosts(posts: {id, clusterId: string, authorId: string | null, lane: Lane, publishedAt: Date}[],
    cfg): Set<id>`. Per cluster, sort by publishedAt and slide a window of nearDupWindowMin (60). When any
    window holds nearDupMinAuthors (5) or more distinct non-null authorIds, every post in that window is flagged.
    Media-lane posts are excluded before counting, because wire-copy syndication across outlets is not
    coordination. Null authors never count. Posts from the same author count once.
  - `median(values: number[]): number`
  - `isBurst(items: number, trailing: number[], cfg): boolean`. Trailing is the 96 prior bucket counts, with
    missing buckets as 0. The result is items > burstMultiplier x median AND items >= burstMinItems (10). The
    floor stops a zero median from flagging every busy quarter hour.
  - `top5Share(postsPerAuthor: number[], total: number, cfg): number | null` returns null when total is below
    top5MinItems (30). Otherwise it returns the sum of the 5 largest counts divided by total, rounded to 2 dp.
  Unit tests: 5 authors in 59 min are flagged; 5 authors spread over 61 min are not; 4 authors posting 10 times
  are not; 5 media-lane outlets are not; null authors are ignored; median([0,0,0,8]) is 0, so isBurst(9, ...) is
  false (floor) and isBurst(12, ...) is true; the median of 96 values of 3 is 3, so 12 is not a burst (it is not
  above 12) and 13 is; top5Share of [10,5,5,5,5,1,1] over 32 is 0.94; a total of 29 gives null.
  The DB function is `detectNearDupCoordination(db, now, cfg): Promise<{flagged: number}>`. It loads social
  posts with a non-null near_dup_cluster_id and published_at >= now - 26h, runs findCoordinatedPosts and sets
  `coord_suspected = true, coord_detected_at = now` on the newly flagged ids. The flag is monotonic: it never
  resets to false. The integration test (DATABASE_URL_TEST) seeds a qualifying cluster and a non-qualifying
  one and asserts only the first is flagged. A second run must not change the row count or coord_detected_at.</action>
