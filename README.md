# Jio IPO sentiment: demo

A static, clickable copy of the jio-ipo-analysis dashboard for demos while the real app is built. It uses the same screens, copy, rules and styling (the shadcn class strings and the `globals.css` theme are copied from `apps/web`). A local script over a scraped-data snapshot replaces the backend.

## Run it

It needs an internet connection, because React, htm and Tailwind load from jsDelivr. There is no build step.

```sh
cd mock-version/demo
python3 -m http.server 8765      # or: npx serve .
# open http://localhost:8765
```

Opening `index.html` directly from disk also works. Sign in with any password. Type `wrong` as the password to see the error state, and after 5 failures the lockout state.

## Screens

| Route | Built from |
|---|---|
| `#/login` | `app/login/*` |
| `#/` executive brief | `components/brief/*`, `components/shell/*` (real 04-02 code), with the 06-01 lane toggle and 06-02 coordination counts |
| Evidence drawer (any number) | `components/evidence/*` (real 04-02 code), with the 05-03 relabel controls and 10-second Undo |
| `#/topics/:slug` | PLAN-04-03 (7-day chart with GMP line, by source, mentions, top posts) and the PLAN-06-02 coordination panel |
| `#/sources` | PLAN-05-01 (status, inline intervals, last 10 runs, X card, YouTube quota) |
| `#/settings` (`?tab=topics`, `?tab=access`) | PLAN-05-02 (keyword chips with "Test against last 24h", topics, Emerging promote / merge / dismiss, retention, audit log, locked person-level switch) |
| `#/accuracy` | PLAN-05-03 (starts at 0 of 200; figures appear once 200 posts are labelled) |

Filters (`entity`, `lane`) and the open drawer (`evidence`) live in the URL, as in the real app, so any view can be linked.

## Data

`js/data.js` is generated by `node build-data.mjs [../scraped-output]` and contains only real data from `../scraped-output/`: items scraped from the web plus the user's CSV extracts, merged and de-duplicated there. Nothing is generated, interpolated or taken from fixtures.

- **Posts:** every line of `all-posts.ndjson` (news, YouTube, Reddit, X, web search and the IPO portal pages). Topic and sentiment are labelled by the worker's rule-based stub classifier on the real text, and entities by the real keyword matcher (`js/core.js`). Language is detected from script (Devanagari, Gujarati, else English), so Hinglish shows as English. There are no English glosses.
- **GMP:** every point in `market-points.json`, as observed. No interpolation.
- **Sources page:** status, fetch time, item counts and notes come from `manifest.json` and the per-source envelopes. Poll intervals, the X tier card and the YouTube quota are not in that data, so they are not shown. Skipped sources show "No data yet".
- **Empty states:** no topic summaries, suggested next steps, Emerging clusters or coordination flags (no clustering or near-duplicate step has run), and an empty audit log (only actions in the current session are logged). The accuracy page starts at 0 of 200 gold labels and computes its figures from labels you enter.
- **Time:** each post stores "minutes before the run's `until` time" (from its real `publishedAt`), resolved against page load, so the snapshot looks live. To refresh, re-run the collector and merge, then `node build-data.mjs ../scraped-output`.

## What differs from the real app

- There is no server. Edits (relabels, intervals, keywords, promotions) last until you reload the page.
- The topic chart is hand-drawn SVG, not Recharts, and selects are native `<select>` elements styled as the shadcn trigger.
- Subscription figures are empty, because bidding has not opened yet. That is true of the real data as well.
